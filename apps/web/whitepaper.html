Abstract#

Auralis turns speech into typed text in any Windows application. The user holds a hotkey, speaks, and releases; the transcript is cleaned and typed into the window that has focus. Every stage, from microphone capture to keystroke injection, runs on the user’s own machine. No audio or text is sent to a cloud service, and the software collects no telemetry.

This paper describes what exists today: a Rust runtime, a Tauri desktop shell, a loopback HTTP API and a benchmark harness. It is deliberately a vertical slice built on an existing open speech model (whisper.cpp), not a custom-trained model or a distributed compute system.

Design goals#

  • Local by default. A dictation tool hears everything the user says. The safest place for that audio is the machine that recorded it.
  • Works everywhere text goes. Insertion happens at the keyboard level, so no per-application plugin is needed.
  • Predictable. If transcription fails, nothing is typed. The user can always select the raw transcript with no rules applied.
  • Separable. The pipeline lives in a reusable library, not inside the desktop app, so the same engine serves the app, the API and the benchmarks.
  • Honest. Accuracy claims need a reproducible command behind them. Until the benchmark has been run on a real corpus, none are made.

Privacy model#

The privacy claim is structural, not a policy promise: the code path from microphone to keystroke contains no network client. The desktop app never downloads anything: speech models are local files that you place in its models folder.

DataWhere it goes
Microphone audioHeld in memory on the PC during the utterance, then discarded after transcription.
TranscriptTyped into the focused window, or copied to the clipboard if typing is blocked.
SettingsA JSON file in the per-user app data folder.
Model filesDownloaded once from the model host into the per-user app data folder.
Usage dataNot collected.

The local API binds to 127.0.0.1 by default. Binding it to another interface is an explicit flag, and the server has no authentication, so doing so is the operator’s decision.

The pipeline#

One utterance passes through these stages in order.

  1. Hotkey. A global hotkey starts capture: Ctrl+Space while held, or Ctrl+Shift+Space toggled for hands-free use. Handlers are guarded so rapid presses cannot deadlock or double-fire.
  2. Capture. Audio is read from the default input device with cpal and resampled to 16 kHz mono.
  3. Quality analysis. Before any processing, the utterance is measured: speech-to-noise ratio in dB, fraction of frames the VAD called speech, RMS level and whether the input clipped. SNR is reported as unavailable instead of a made-up number when the buffer lacks speech or noise frames.
  4. Voice activity detection. webrtc-vad trims leading and trailing silence from the held segment.
  5. Denoising. RNNoise, through the pure-Rust nnnoiseless crate, suppresses steady background noise.
  6. Transcription. whisper.cpp, through whisper-rs, decodes the audio with quantised GGUF weights. Decoding uses beam search (width 5), whisper.cpp’s temperature-fallback thresholds and no_context, which together suppress the repetition loops that greedy decoding with carried-over context can fall into.
  7. Text cleanup. Local rules shape the transcript according to the selected mode.
  8. Insertion. Keystrokes are simulated with enigo. If the target window rejects them, the text goes to the clipboard and the user is told.

Model size is the largest accuracy lever. base.en (about 59 MB) is the fast default. small.en (about 190 MB) is better on proper nouns and accented speech at roughly three times the decode cost. Both run on CPU; the runtime can be built with cuda or vulkan features for GPU decoding.

Text cleanup and spoken corrections#

How much the software may rewrite what you said is a setting, not a hidden behaviour.

ModeFiller words removedCapitalisedTerminal punctuation
rawNoNoNo
clean (default)NoYesYes
polishedYesYesYes
developerYesNoNo

developer exists because dictating cargo test --locked into a terminal should not gain a capital letter or a full stop. Filler removal is conservative: only tokens that are not also ordinary words, so “summary” and “ahead” survive while a standalone “um” does not.

Spoken corrections. Saying “actually, change X to Y” makes Auralis backspace the text it just typed and replace it in place. Because this deletes characters in someone else’s window, it only applies to text Auralis itself typed, and the opportunity expires 45 seconds after insertion.

System architecture#

apps/desktop      Tauri 2 shell: hotkeys, tray, status overlay, settings,
                  single-instance guard, JSON config, model download
runtime/core      auralis-runtime (Rust library)
                    audio · resample · quality · vad · denoise
                    stt · text · pipeline
                  bins: auralis-server (HTTP API), auralis-router (multi-node
                  gateway), auralis-bench-cli
infra/            Dockerfile, Compose, Prometheus and Grafana config
benchmarks/       Python harness: dataset prep, runners, WER/CER/RTF metrics
.github/          CI (tests, clippy) and tag-driven NSIS release

The library/shell split keeps the engine independent of any one front end. The desktop app, the API server and the benchmark CLI are three callers of the same Pipeline.

Local API#

auralis-server loads one model and serves it over HTTP, by default on 127.0.0.1:8787.

RequestBehaviour
GET /healthzReturns status and the loaded model name.
POST /v1/transcriptions?cleanup=<mode>Body is a WAV file (up to 50 MB). Returns text, duration_s, processing_s and model. An unknown cleanup mode returns 400; an oversized body returns 413.
 
auralis-server --model base.en.bin
curl -X POST "http://127.0.0.1:8787/v1/transcriptions?cleanup=clean" --data-binary @speech.wav

Measurement#

The benchmark harness compares model size (tiny, base, small) against preprocessing (raw audio versus VAD plus denoise) on a clean LibriSpeech slice and a synthetically noised copy. It reports word error rate, character error rate and real-time factor, and scores against normalised reference text so the cleanup rules do not distort the comparison. The guiding rule: a denoiser that makes audio sound better but transcription worse is a failed component.

Status. The harness exists and its tests pass. It has not been run against a real corpus, so this paper publishes no accuracy or speed numbers. When results exist they will be added together with the exact commands that produced them.

Limitations#

  • Windows only. Insertion code sits behind a platform boundary, but no other backend exists.
  • English-focused default models. Multilingual models can be loaded but are untested here.
  • Text cleanup is rule-based. It does not understand meaning, so it will not fix a mis-heard word.
  • Some elevated or protected windows block simulated input; those fall back to the clipboard.
  • The release workflow and code signing have not been exercised end to end, and GPU builds need the CUDA or Vulkan toolkit. Windows SmartScreen may warn on unsigned installers.
  • The local API has no authentication and is intended for loopback use only.

Roadmap#

Not built, and not promised on a date: macOS and Linux insertion backends, context-aware vocabulary, additional languages, and run-and-publish benchmark results. The original product requirements describe a much larger system, including a custom-trained model family and a self-hosted compute fabric. Those are out of scope for this release and are not implied by anything above.
